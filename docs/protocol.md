# Протокол bitvm v0.1

Статус: согласован 2026-11-01, реализован на этапе M1 в `shared/`. Архитектурный контекст —
`docs/architecture.md`.

Пока major-версия равна 0, совместимости между версиями нет: клиент и сервер обязаны совпадать и по
версии протокола, и по каталогу юнитов (§5).

## 1. Термины

| Термин | Значение |
|--------|----------|
| сервер | `bitvmd` |
| клиент | процесс, подключённый к серверу: `sona`, `bitvmctl` |
| сообщение | единица транспорта, ровно один пакет сокета |
| команда | одна операция внутри `BUNDLE` или `CALL` |
| бандл | RT-команды с общей меткой времени |
| вызов | одна не-RT команда, на которую сервер отвечает `REPLY` |
| фрейм | один сэмпл на всех каналах |
| блок | `block_size` фреймов (64), единица работы audio thread |
| уровень 1 / уровень 2 | проверки до исполнения и во время исполнения (§9) |

## 2. Транспорт

- `AF_UNIX` + `SOCK_SEQPACKET`. Одно соединение — один клиент. Клиент и сервер всегда на одном хосте.
- Путь сокета: `$XDG_RUNTIME_DIR/sonasphere/bitvm.sock`, у именованного сервера (`bitvmd --name foo`)
  — `bitvm-foo.sock`. Если `XDG_RUNTIME_DIR` не задан, каталог — `/tmp/sonasphere-<uid>/`.
- Сервер создаёт каталог с правами 0700. Если каталог принадлежит другому пользователю или доступен
  кому-то ещё, сервер не стартует.
- Если файл сокета уже существует, сервер пробует к нему подключиться. Подключился — значит, работает
  другой сервер, и старт завершается ошибкой. Получил `ECONNREFUSED` — файл остался от упавшего
  сервера, его можно удалить.
- Максимальный размер сообщения — 65536 байт в обе стороны (`max_message` в `WELCOME`). Обе стороны
  выставляют `SO_SNDBUF` не меньше 256 КиБ, чтобы такое сообщение помещалось в буфер сокета.
- Сервер работает с сокетами неблокирующе (epoll или io_uring) и никогда не ждёт медленного клиента.
  Если буфер клиента полон, `EVENT` выбрасывается и учитывается в `events_dropped`. Если не удаётся
  отправить `REPLY` или `WELCOME`, сервер разрывает соединение. Клиенту отправлять блокирующе можно.
- Отключение клиента не останавливает звук: его узлы и ресурсы остаются. С флагом
  `bitvmd --free-on-disconnect` сервер при отключении делает то же, что `client.reset` (§10).

## 3. Кодирование значений

Порядок байт little-endian, выравнивания и паддинга нет. Декодер читает байты через `memcpy` и никогда
через `reinterpret_cast`.

| Тип | Кодирование |
|-----|-------------|
| `u8`, `u16`, `u32`, `u64` | беззнаковые целые |
| `i64` | знаковое целое, дополнительный код |
| `f32` | IEEE 754 binary32. Только конечные значения: NaN и ±Inf в v0 не допускаются ни в одном поле |
| `bool` | `u8`, строго 0 или 1 |
| `str` | `u16` длина + байты без завершающего нуля, не длиннее 1024 байт (у `path` свой предел). Декодер не проверяет UTF-8, текстовая форма экранирует непечатаемые байты |
| `name` | `str` из `[A-Za-z_][A-Za-z0-9_]*`, 1–63 байта |
| `path` | `str` длиной 1–4095 байт без байта 0; общий предел `str` в 1024 байта на него не действует |
| `blob` | `u32` длина + байты |
| `list<T>` | `u16` число элементов + элементы подряд |
| `pair` | `index: u16`, `value: f32` — значение параметра узла |

Перечисления:

| Тип | Значения |
|-----|----------|
| `add` (`u8`) | 0 `head` — первым в группе `target`; 1 `tail` — последним в группе `target`; 2 `before` — перед узлом `target`; 3 `after` — после узла `target`; 4 `replace` — на место узла `target`, который освобождается |
| `bus_kind` (`u8`) | 0 `audio`, 1 `control` |
| `curve` (`u8`) | 0 `lin`; остальные значения зарезервированы |
| `rate` (`u8`) | 0 `ir` — один раз при создании узла; 1 `kr` — раз в блок; 2 `ar` — каждый фрейм |

Значение перечисления не из таблицы — ошибка декодирования.

## 4. Сообщения

### Заголовок (12 байт)

| Смещение | Тип | Поле | Смысл |
|----------|-----|------|-------|
| 0 | `u32` | `length` | полная длина сообщения вместе с заголовком, 12–65536; обязана совпадать с длиной пакета |
| 4 | `u16` | `kind` | вид сообщения |
| 6 | `u16` | `flags` | в v0 всегда 0 |
| 8 | `u32` | `seq` | см. ниже |

### Виды сообщений

| `kind` | Имя | Направление | Полезная нагрузка |
|--------|-----|-------------|-------------------|
| 1 | `HELLO` | клиент → сервер | §5 |
| 2 | `WELCOME` | сервер → клиент | §5 |
| 3 | `REJECT` | сервер → клиент | §5 |
| 4 | `BUNDLE` | клиент → сервер | `time: i64`, затем одна или больше RT-команд до конца сообщения |
| 5 | `CALL` | клиент → сервер | ровно одна команда-вызов |
| 6 | `REPLY` | сервер → клиент | `opcode: u16`, `status: u16`; при `status = 0` — результат вызова (§10), иначе `message: str` |
| 7 | `EVENT` | сервер → клиент | ровно одно событие (§11) |

### `seq`

- В сообщениях клиента `seq` выбирает клиент; рекомендуется увеличивать его на 1 с каждым
  сообщением. `REPLY` повторяет `seq` своего `CALL`, `WELCOME` и `REJECT` — `seq` из `HELLO`,
  событие `error` ссылается на `seq` бандла.
- В `EVENT` `seq` — счётчик событий этого соединения, начиная с 1. Пропуск номера означает, что
  события терялись.

### Команда

Команды внутри `BUNDLE` и `CALL` и событие внутри `EVENT` кодируются одинаково:

| Смещение | Тип | Поле |
|----------|-----|------|
| 0 | `u16` | `opcode` |
| 2 | `u16` | `size` — размер команды вместе с этими 4 байтами |
| 4 | … | поля в порядке из таблиц §8, §10, §11 |

Поля обязаны занимать ровно `size − 4` байт: и недостача, и лишние байты — ошибка. Благодаря `size`
декодер сообщает индекс ошибочной команды, а дизассемблер показывает незнакомую команду и идёт дальше.

### Нарушения протокола

Сервер разрывает соединение без ответа, если:

- `length` не совпадает с длиной пакета или лежит вне 12–65536;
- `kind` неизвестен или это вид, который отправляет только сервер;
- `flags ≠ 0`;
- первое сообщение — не `HELLO`, или `HELLO` пришёл повторно.

Ошибки внутри `BUNDLE` и `CALL` соединение не рвут: на них сервер отвечает (§9, §10).

## 5. Хендшейк

`HELLO` — первое сообщение клиента. Если его нет 5 секунд, сервер закрывает соединение.

| Сообщение | Поля |
|-----------|------|
| `HELLO` | `magic: u32`, `major: u16`, `minor: u16`, `catalog_hash: u64`, `requested_client: u8`, `events: u32`, `name: str` |
| `WELCOME` | `magic: u32`, `major: u16`, `minor: u16`, `catalog_hash: u64`, `client_id: u8`, `id_base: u32`, `id_count: u32`, `sample_rate: u32`, `block_size: u16`, `out_channels: u16`, `in_channels: u16`, `audio_buses: u32`, `control_buses: u32`, `max_buffers: u32`, `output_latency_ns: i64`, `late_tolerance_ns: i64`, `max_message: u32`, `server_now_ns: i64`, `server: str` |
| `REJECT` | `code: u16`, `message: str`; после него сервер закрывает соединение |

- `magic` — байты `B V M P` (как `u32` LE — `0x504D5642`).
- Версия этой спецификации: `major = 0`, `minor = 1`. Пока `major = 0`, сервер требует точного
  совпадения `major`, `minor` и `catalog_hash`, иначе отвечает `REJECT` с кодом `version`.
- `catalog_hash` — хэш каталога юнитов (§14). Каталог статичен и собирается в обе программы из
  `shared/`; хэш ловит рассинхрон сборок sona и bitvmd.
- `requested_client` — желаемый номер клиента 1–255, 0 — любой. Свободный номер сервер выдаёт: так
  перезапущенная sona возвращает себе свои старые узлы и ресурсы. Занятый — сервер выдаёт наименьший
  свободный. Свободных нет — `REJECT` с кодом `limit`.
- `events` — подписка на события: бит 0 `n_end`, бит 1 `late`, бит 2 `xrun`. Остальные биты — 0.
  Событие `error` приходит всегда.
- `id_base = client_id << 24`, `id_count = 2^24` (§7).

## 6. Время

- `time` в бандле — момент `CLOCK_MONOTONIC` хоста в наносекундах, когда первый сэмпл результата
  должен прозвучать на выходе. Задержку устройства сервер компенсирует сам.
- `time = 0` — «как можно скорее»: бандл исполняется в начале ближайшего блока и никогда не
  опаздывает. Отрицательное `time` — ошибка декодирования.
- Бандлы исполняются в порядке времени, при равном времени — в том порядке, в котором их обработал
  control thread.
- Все команды бандла применяются в один фрейм, последовательно, в порядке записи. Узлы, созданные
  бандлом, звучат точно с этого фрейма. Изменение параметров уже звучащих узлов может быть квантовано
  к границе блока, то есть запоздать не больше чем на `block_size` фреймов.
- **Опоздание.** Если к моменту исполнения `time` уже прошло, сервер сравнивает опоздание с
  `late_tolerance_ns` (опция `bitvmd`, по умолчанию 50 мс, сообщается в `WELCOME`). Не больше порога —
  бандл исполняется в первый фрейм текущего блока. Больше — бандл выбрасывается целиком. Оба случая
  учитываются в событии `late` и в `status`.

## 7. Объекты и идентификаторы

### Узлы и группы

- Синты и группы делят одно пространство ID `u32`. ID 0 — корневая группа: она есть всегда, её нельзя
  освободить, но можно очистить.
- Клиент с номером `k` (1–255) владеет диапазоном `[k << 24, (k + 1) << 24)`. Создавать узлы он может
  только с ID из своего диапазона, а обращаться (`set`, `free`, `move`, `run`, `clear`) — к любым.
  Диапазон `[1, 2^24)` зарезервирован за сервером и в v0 не используется.
- ID освободившегося узла можно снова использовать после события `n_end`. Повторное использование
  живого ID — ошибка уровня 2 (`exists`).

### Ресурсы

GraphDef, буферы и шины создаются вызовами, и их номера выдаёт сервер в `REPLY`. Номера буферов и шин
попадают внутрь DSP-графа как значения `f32`, а `f32` хранит целые точно только до 2^24. Плотные
номера от сервера туда помещаются, номера с клиентом в старших битах — нет.

| Ресурс | Номера | Выделение |
|--------|--------|-----------|
| GraphDef | `u32`, с 1 | монотонный счётчик; номера не переиспользуются за жизнь сервера |
| Буфер | `0 … max_buffers − 1` | наименьший свободный |
| Аудиошина | `0 … audio_buses − 1` | `[0, out_channels)` — выходы карты, `[out_channels, out_channels + in_channels)` — входы; остальные выделяются диапазонами, first-fit |
| Контрольная шина | `0 … control_buses − 1` | диапазонами, first-fit |

Выделение детерминировано: одинаковая последовательность вызовов на свежем сервере даёт одинаковые
номера. На этом держатся партитуры и тесты (§16).

### Владение

Узел принадлежит клиенту, в чьём диапазоне лежит его ID. Ресурс принадлежит клиенту, который его
создал. Владение определяет три вещи: кому уходит `n_end`, что освобождает `client.reset` и что
освобождает `--free-on-disconnect`.

### Параметры узла

Параметр — значение `f32` уровня `kr`, адресуется индексом из GraphDef. Значения, не переданные в
`node.new`, берутся из умолчаний GraphDef. Ramp обновляет значение не реже раза в блок.

## 8. Команды бандла (RT)

| Opcode | Команда | Поля | Действие |
|--------|---------|------|----------|
| `0x0100` | `node.new` | `id: u32`, `def: u32`, `add: add`, `target: u32`, `flags: u8`, `params: list<pair>` | создать синт из GraphDef. `flags`: бит 0 — создать на паузе, остальные биты — 0 |
| `0x0101` | `group.new` | `id: u32`, `add: add`, `target: u32` | создать пустую группу |
| `0x0102` | `node.free` | `ids: list<u32>` | освободить узлы; группа освобождается вместе с поддеревом |
| `0x0103` | `node.set` | `id: u32`, `ramp: f32`, `curve: curve`, `params: list<pair>` | за `ramp` секунд (0 — сразу) перевести параметры синта от текущего значения к новому. Новый `set` параметра отменяет его незаконченный ramp. Если индекс в списке повторяется, побеждает последний |
| `0x0104` | `node.run` | `id: u32`, `run: bool` | пауза и продолжение; у группы — всего поддерева |
| `0x0105` | `node.move` | `id: u32`, `add: add`, `target: u32` | переместить синт или группу; `replace` недопустим |
| `0x0106` | `group.clear` | `id: u32` | освободить всё содержимое группы, сама группа остаётся. `group.clear` корня — это «hush» |
| `0x0107` | `cbus.set` | `index: u32`, `values: list<f32>` | записать значения в контрольные шины `index … index + n − 1` |

Синт на паузе не вычисляется и не пишет в шины, его огибающие стоят.

## 9. Ошибки бандла: два уровня

### Уровень 1 — до исполнения

Проверки, которым не нужно дерево узлов. Любой провал отбрасывает бандл целиком: в audio thread не
уходит ничего, клиент получает событие `error` с `level = 1`, сервер пишет в лог. Такая ошибка —
баг генератора команд.

| Кто проверяет | Что |
|---------------|-----|
| декодер (`shared/`) | формат, длины, перечисления, `bool`, конечность `f32`, длины строк, лишние байты; команда допустима для вида сообщения (иначе `context`) |
| статическая проверка (`shared/`) | смысл без состояния сервера: `0 ≤ ramp ≤ 3600`; `target ≠ id`; в `node.free` список не пуст и не содержит 0; в `node.move` нет `replace`; список `cbus.set` не пуст; параметров в одной команде не больше 256 |
| сервер (`bitvm`) | то, что знает control thread: `def` существует; индексы параметров в `node.new` меньше числа параметров def; ID создаваемых узлов лежат в диапазоне клиента; шины `cbus.set` существуют; хватает места в RT-очереди и памяти под экземпляры |

### Уровень 2 — во время исполнения

Проверки, которые зависят от дерева узлов в момент исполнения. Их делает audio thread.

**Мягкие.** Команда пропускается, бандл исполняется дальше, растёт счётчик `skipped` в `status`. Это
обычные гонки: синт успел освободить себя сам раньше, чем пришла команда.

- `node.set`, `node.run`, `node.free`, `node.move`, `group.clear`: узла `id` нет.
- `node.set` на группе; `group.clear` на синте.

**Жёсткие.** Исполнение бандла прерывается, оставшиеся команды не выполняются. Узлы и группы, которые
этот бандл успел создать, сразу освобождаются вместе с поддеревьями. Ни одного сэмпла они ещё не
выдали, поэтому откат не слышен, а «зомби» в дереве не остаются. На каждый откатанный узел уходит
`n_end`, клиент получает `error` с `level = 2`. Уже выполненные команды, которые ничего не создавали
(`set`, `free`, `move`, `run`), остаются в силе.

- `node.new`, `group.new`: `id` уже занят (`exists`); `target` нет (`not_found`); для `head` или
  `tail` `target` — не группа (`invalid_arg`).
- `node.set`: индекс параметра не меньше числа параметров def узла (`invalid_arg`).
- `node.move`: `target` нет (`not_found`); группу перемещают внутрь её собственного поддерева или
  `target` для `head`/`tail` — не группа (`invalid_arg`).
- Переполнены RT-таблицы (`limit`).

Опоздавший сверх порога бандл (§6) тоже выбрасывается целиком, но ошибкой не считается: о нём
сообщает событие `late`.

## 10. Вызовы (CALL)

Вызовы клиента обрабатываются в порядке прибытия, вперемешку с его бандлами. Синхронный вызов
завершается раньше, чем начинается обработка следующего сообщения. Асинхронный (`buf.load`)
завершается позже, и его `REPLY` может прийти не по порядку.

| Opcode | Вызов | Поля | Результат | Примечание |
|--------|-------|------|-----------|------------|
| `0x0001` | `sync` | — | — | ответ приходит, когда завершены все более ранние асинхронные вызовы этого клиента и audio thread применил все его более ранние бандлы с `time = 0` |
| `0x0002` | `status` | — | см. ниже | |
| `0x0003` | `tree` | `root: u32`, `depth: u16` | `truncated: bool`, `entries: list<entry>` | `depth = 0` — без ограничения. Обход в порядке исполнения, первым идёт сам `root` |
| `0x0004` | `client.reset` | — | — | освобождает узлы из диапазона клиента вместе с поддеревьями и все его ресурсы. Ответ — после того как audio thread это применил |
| `0x0010` | `def.load` | `graph: blob` | `def: u32` | GraphDef из §13; невалидный — ошибка `graph` |
| `0x0011` | `def.free` | `def: u32` | — | новые узлы с этим def сразу же создавать нельзя; память освобождается, когда закончится последний его узел |
| `0x0020` | `buf.alloc` | `frames: u32`, `channels: u16` | `buf: u32` | обнулённый буфер с частотой сервера |
| `0x0021` | `buf.load` | `path: path`, `start: u32`, `frames: u32` | `buf: u32`, `frames: u32`, `channels: u16`, `sample_rate: u32` | асинхронный. `frames = 0` — до конца файла. Частота файла сохраняется, ресемплинга нет. Ошибки `io`, `format` |
| `0x0022` | `buf.free` | `buf: u32` | — | синты, читающие буфер, дальше читают тишину |
| `0x0030` | `bus.alloc` | `kind: bus_kind`, `count: u16` | `base: u32` | непрерывный диапазон шин |
| `0x0031` | `bus.free` | `kind: bus_kind`, `base: u32` | — | освобождает весь диапазон, выделенный начиная с `base` |

- `entry` в `tree`: `id: u32`, `parent: u32` (у `root` — `0xFFFFFFFF`), `kind: u8` (0 группа,
  1 синт), `def: u32` (у группы 0), `running: bool`. Если дерево не помещается в одно сообщение,
  `truncated = 1`.
- Результат `status`: `now_ns: i64`, `sample_rate: u32`, `block_size: u16`, `cpu_avg: f32`,
  `cpu_peak: f32`, `nodes: u32`, `groups: u32`, `defs: u32`, `buffers: u32`, `rt_queue_used: u32`,
  `rt_queue_capacity: u32`, `late_played: u64`, `late_dropped: u64`, `skipped: u64`, `xruns: u64`,
  `events_dropped: u64`. Загрузка CPU — доля времени блока: `cpu_avg` — средняя за последнюю секунду,
  `cpu_peak` — пик с прошлого `status`. Все счётчики общие для сервера, кроме `events_dropped` — он
  по этому клиенту.
- Буфер: `channels` 1–16, `frames ≥ 1`. Предел памяти под буферы — опция сервера; при превышении —
  ошибка `limit`.
- Неуспешный `REPLY`: `opcode` вызова (0, если его не удалось прочитать), `status` — код ошибки
  (§12), `message` — пояснение.

## 11. События

| Opcode | Событие | Поля | Кому |
|--------|---------|------|------|
| `0x8001` | `n_end` | `id: u32` | владельцу `id`, если он подписан. Уходит для каждого синта и группы, покинувших дерево, по любой причине: сам закончился, `node.free`, `group.clear`, откат, `client.reset` |
| `0x8002` | `late` | `played: u32`, `dropped: u32`, `max_late_ns: i64` | отправителю опоздавших бандлов, если он подписан. Сводка с прошлого `late`, не чаще 4 раз в секунду |
| `0x8003` | `xrun` | `count: u32` | всем подписанным; число xrun с прошлого события |
| `0x8004` | `error` | `bundle_seq: u32`, `index: u16`, `opcode: u16`, `code: u16`, `level: u8`, `message: str` | отправителю бандла, всегда. `index` — номер команды в бандле, `0xFFFF` — ошибка не про конкретную команду |

## 12. Коды ошибок

| Код | Имя | Когда |
|-----|-----|-------|
| 0 | `ok` | успех |
| 1 | `malformed` | сообщение или команда не декодируются |
| 2 | `unsupported` | неизвестный opcode, ненулевые флаги, зарезервированное значение |
| 3 | `version` | не совпали версия или `catalog_hash` |
| 4 | `context` | RT-команда в `CALL` или вызов в `BUNDLE` |
| 5 | `invalid_arg` | значение вне допустимого: NaN или Inf, индекс параметра, `ramp`, неподходящий `target` |
| 6 | `not_found` | нет такого def, буфера, шины, узла или `target` |
| 7 | `exists` | ID уже занят |
| 8 | `id_range` | ID создаваемого узла вне диапазона клиента |
| 9 | `limit` | исчерпан ресурс: RT-очередь, таблица узлов, память, номера клиентов |
| 10 | `io` | файл не открылся или не прочитался |
| 11 | `format` | формат аудиофайла не поддерживается |

| 13 | `internal` | внутренняя ошибка сервера |

## 13. GraphDef

### Бинарный формат

```
graphdef = magic    u32           "BVGD"
           version  u16           1
           name     str
           params   list<param>
           consts   list<f32>
           types    list<name>    имена типов юнитов из каталога
           units    list<unit>

param    = name: name, default: f32

unit     = type:   u16            индекс в types
           rate:   rate
           n_out:  u8
           n_in:   u8, затем input × n_in

input    = src:    u8             0 константа, 1 параметр, 2 выход юнита
           index:  u16            индекс константы, параметра или юнита
           output: u8             номер выхода юнита; для src 0 и 1 — 0
```

### Валидация

Валидатор один, в `shared/`. Его вызывает sona перед отправкой и bitvm при загрузке. Граф
отклоняется, если:

1. Не совпали `magic` или `version`, или после `units` остались байты.
2. Имена параметров повторяются.
3. Превышены пределы: параметров больше 256, констант больше 4096, юнитов больше 4096, входов у
   юнита больше 65 (`out`: `bus` и до 64 каналов), выходов у юнита больше 64.
4. Типа юнита нет в каталоге, `rate` не входит в допустимые для типа, `n_out` или число входов не
   соответствуют сигнатуре.
5. Вход ссылается на несуществующую константу или параметр, на юнит с индексом не меньше текущего
   (поэтому граф ацикличен по построению) или на несуществующий выход.
6. Юнит с `rate = ir` берёт вход у юнита `kr` или `ar`. Юнит `ir` вычисляется один раз при создании
   узла и может зависеть только от констант, параметров (по начальному значению) и других юнитов `ir`.

Юниты исполняются в порядке записи. Неиспользуемые юниты допустимы, но генератору лучше их не выдавать.

Граф передаётся одним `def.load`, поэтому его размер ограничен `max_message`. С пределами из п. 3
это около тысячи юнитов — для инструмента и эффекта с запасом.

### Каноническая форма

Энкодер в `shared/` выдаёт граф детерминированно: параметры — в порядке объявления; `types` и
`consts` — без повторов, в порядке первого использования (константы сравниваются побитово). Декодер
принимает и неканонические графы.

### Преобразование rate

Каждый вход читается так, как сказано в каталоге (`ir`, `kr` или `ar`), независимо от rate источника.
Источник `ar`, прочитанный как `kr`, даёт первый сэмпл блока. Источник `kr`, прочитанный как `ar`,
постоянен в пределах блока; интерполировать внутри блока юнит может сам.

## 14. Каталог юнитов

Каталог — таблица-данные в `shared/`, общая для sona и bitvm. bitvm при старте проверяет, что
реализовал каждую запись. Новый юнит = запись в каталоге + реализация в bitvm + новая `minor`-версия.

Запись каталога содержит:

- `name` — нижний регистр, `snake_case`;
- допустимые rate юнита;
- входы: имя, значение по умолчанию или пометка «обязателен», способ чтения (`ir`, `kr` или `ar`).
  Последний вход может быть вариадическим — с минимумом и максимумом повторов;
- выходы: фиксированное число или диапазон (тогда число задаёт `n_out` в GraphDef);
- флаг `done` — юнит умеет заканчиваться и освобождать узел;
- однострочное описание.

`catalog_hash` — FNV-1a 64 от канонического текстового представления каталога, которое печатает
`shared/`. Реализация одна на обе стороны, поэтому точный вид этих строк — её внутреннее дело.

### Каталог v0

Минимальный набор для M2. M4 его расширяет.

| Юнит | Rate | Входы: умолчание, чтение | Выходы | Что делает |
|------|------|--------------------------|--------|------------|
| `add`, `sub`, `mul` | ir kr ar | `a`: обяз.; `b`: обяз. Оба читаются с rate юнита | 1 | `a + b`, `a − b`, `a · b` |
| `div` | ir kr ar | `a`, `b` — как выше | 1 | `a / b`; при `b = 0` — 0 |
| `sin_osc` | kr ar | `freq`: 440, rate юнита; `phase`: 0, ir | 1 | синус амплитуды 1; `phase` — в оборотах, [0, 1) |
| `env_perc` | kr ar | `attack`: 0.01; `release`: 1; `level`: 1; `curve`: −4; `done`: 0. Все ir | 1 | от старта узла: подъём 0 → `level` за `attack` секунд, затем спад до 0 за `release` секунд; оба сегмента — с кривизной `curve` |
| `env_asr` | kr ar | `gate`: 1, kr; `attack`: 0.01, ir; `level`: 1, ir; `release`: 0.3, ir; `done`: 0, ir | 1 | пока `gate > 0` — линейный подъём к `level` за `attack` и удержание; когда `gate ≤ 0` — линейный спад к 0 за `release`. Новый `gate > 0` снова поднимает от текущего значения. Если `gate ≤ 0` уже при старте, огибающая сразу закончена |
| `out` | kr ar | `bus`: обяз., kr; `channels…`: обяз., вариадический 1–64, rate юнита | 0 | `ar`: прибавляет канал `i` к аудиошине `bus + i`. `kr`: записывает канал `i` в контрольную шину `bus + i`. Шина вне диапазона — запись пропускается |
| `in` | kr ar | `bus`: обяз., kr | 1–64 | читает шины `bus … bus + n_out − 1`; вне диапазона — 0 |

- `done`: 0 — ничего, 1 — освободить узел, когда огибающая закончилась.
- Кривизна `curve = c` для сегмента от `y0` к `y1` на доле сегмента `t ∈ [0, 1]`: при `c = 0` —
  линейно, иначе `y0 + (y1 − y0) · (1 − e^{c·t}) / (1 − e^c)`.
- Номер шины — ближайшее целое к значению входа; отрицательный номер — вне диапазона.
- Аудиошины обнуляются в начале каждого блока. `out.ar` суммирует, `in.ar` читает то, что записано
  раньше в этом же блоке. Контрольные шины хранят значение между блоками; `out.kr` и `cbus.set` его
  перезаписывают.

## 15. Текстовая форма

Нужна для `bitvmd --trace`, `bitvmctl`, golden-тестов sona и текстовых партитур. Ассемблер и
дизассемблер живут в `shared/` и сами ввода-вывода не делают.

### Лексика

- `#` до конца строки — комментарий (вне кавычек). Пустые строки пропускаются.
- Числа: целые десятичные или `0x…`; дробные — `-1.5`, `1e-3`, `440`. `nan` и `inf` — ошибка.
- Строки: «голое» слово без пробелов, `"`, `#` и `=` либо `"…"` с экранированием `\"`, `\\`, `\n`,
  `\t`, `\xNN`.
- Списки пишутся через запятую без пробелов: `ids=0x01000001,0x01000002`.
- Значения перечислений пишутся по имени: `add=tail`, `kind=audio`, `curve=lin`, коды ошибок из §12,
  `events=n_end,late` или `events=none`.

### Сообщения

```
hello[/seq] major=0 minor=1 catalog_hash=0x... requested_client=0 events=n_end,late,xrun name=sona
@<time>[/seq] <команда>
@<time>[/seq] {
  <команда>
  ...
}
call[/seq] <вызов>
reply/<seq> <вызов> ok <поля результата>
reply/<seq> <вызов> err=<код> msg="..."
welcome/<seq> <поля>
reject/<seq> code=<код> msg="..."
event/<seq> <событие> <поля>
```

- `<time>`: `now` (то же, что 0); целое — абсолютные наносекунды; `+<секунды>` — относительно базы,
  которую задаёт вызывающий код (`bitvmctl` — момент отправки, партитура — начало рендера).
- `seq` можно опустить, тогда его назначает вызывающий код. `magic` в тексте не пишется.
- Команда: `<имя> ключ=значение …`. Ключи — имена полей из §5, §8, §10, §11, порядок любой. Поля
  с умолчанием можно опускать: `ramp=0`, `curve=lin`, `depth=0`, `start=0` и `frames=0` в
  `buf.load`. Вместо `flags` у `node.new` пишется `paused=1`.
- Результат `tree`: `truncated=<0|1> entries=<id>:<parent>:<kind>:<def>:<running>,…`, где `kind` —
  `group` или `synth`, `id` и `parent` — в hex (у корня `parent` — `0xffffffff`). Пустой список —
  `entries=` без значения.
- Параметры: `$<индекс>=<значение>` или `$<имя>=<значение>`. Имена разрешаются только через контекст
  «def → имена параметров», который передаёт вызывающий код; без контекста `$имя` — ошибка.
- `def.load`: `graph=base64:<…>`. Если вызывающий код передал загрузчик файлов, можно писать
  `graph=@path/to/file.bvg` — файл в текстовой форме графа.

Пример:

```
call def.load graph=@ping.bvg
@now group.new id=0x01000001 add=head target=0
@+0.5 node.new id=0x01000002 def=1 add=tail target=0x01000001 $freq=440 $amp=0.2
@+1.0 {
  node.set id=0x01000002 ramp=0.05 $amp=0
  node.free ids=0x01000003
}
```

### Каноническая печать

Дизассемблер печатает поля в порядке таблиц и опускает поля, равные умолчанию. ID узлов (`id`,
`target`, `ids`, `root`, `parent`) печатаются в hex, остальные целые — десятично, `f32` — кратчайшей
записью, которая читается обратно в то же значение. Параметры печатаются по имени, если контекст знает
def узла, иначе по индексу. Для канонического сообщения `бинарь → текст → бинарь` даёт те же байты.

### Текстовая форма GraphDef (`.bvg`)

```
graph ping
param freq 440
param amp 0.2

%osc = sin_osc.ar $freq
%env = env_perc.kr 0.005 0.4 1 -4 1
%sig = mul.ar %osc %env
%out = mul.ar %sig $amp
out.ar 0 %out %out
```

- Первая значимая строка — `graph <имя>`, затем строки `param <имя> <умолчание>`, затем юниты.
- Юнит: `[%метка[:n] =] <тип>.<rate> <аргумент> …`, где `rate` — `ir`, `kr` или `ar`; `:n` задаёт
  число выходов у юнитов с переменным числом выходов.
- Аргумент: число → константа; `$имя` или `$индекс` → параметр; `%метка` → выход 0; `%метка.k` →
  выход `k`.
- Опущенные хвостовые аргументы берутся из умолчаний каталога; если у обязательного входа нет
  аргумента — ошибка. Вариадический вход забирает все оставшиеся аргументы.
- Дизассемблер печатает метки `%0`, `%1`, … по индексу юнита, все аргументы явно, а `:n` — только у
  юнитов с переменным числом выходов. `текст → бинарь` всегда даёт каноническую форму (§13).

## 16. Партитуры (offline)

Партитура — поток сообщений для offline-рендера. Бывает текстовой (`.bvs` — текстовая форма без
`hello`) и бинарной (`.bvsb`: `magic: u32` = `"BVSC"`, `major: u16`, `minor: u16`,
`catalog_hash: u64`, затем сообщения подряд, каждое ограничено своим `length`).

- В партитуре только `BUNDLE` и `CALL`. Она исполняется от имени клиента 1 (`id_base = 0x01000000`),
  события отбрасываются или пишутся в лог рендерера.
- Время отсчитывается от начала рендера: `+1.5` — полторы секунды от начала. `now` (и 0) — текущая
  позиция рендера, то есть время предыдущего бандла (в начале партитуры — 0).
- Времена бандлов не убывают, иначе — ошибка. Бандлы `now` в этой проверке не участвуют.
- Вызовы, включая `buf.load`, выполняются синхронно и в порядке файла. Номера ресурсов
  детерминированы (§7): первый `def.load` в партитуре даёт def 1.

## 17. Обязанности клиента

1. Использовать def, буфер или шину в бандлах только после успешного `REPLY` на их создание.
2. Создавать узлы только с ID из своего диапазона и переиспользовать ID только после `n_end`.
3. Структурные бандлы — группы, эффекты, маршрутизацию — отправлять с `time = 0`: они не опаздывают,
   и ноты не теряют свою цель.
4. Держать lookahead не меньше `output_latency_ns` с запасом и увеличивать его, когда приходит `late`.
5. Прогонять перед отправкой статическую проверку и валидатор GraphDef из `shared/` — ошибки уровня 1
   ловятся ещё у себя.
6. Бандл больше `max_message` делить на несколько бандлов с тем же `time`. Атомарность между ними не
   гарантируется: уровень 1 проверяет каждый бандл отдельно.

## 18. Реализация в `shared/` (этап M1)

### Модули

Заголовки — в `include/bitvm/proto/`, пространство имён `bitvm::proto`. Исключений нет, ошибки —
через `std::expected`. Аллокации разрешены: audio thread библиотеку не вызывает.

| Модуль | Содержимое |
|--------|------------|
| `types` | ID, перечисления (`AddAction`, `Rate`, `BusKind`, `Curve`, `ErrorCode`, `MessageKind`, `Opcode`), константы: версия, magic, пределы |
| `messages` | структуры сообщений; команды, результаты вызовов и события — через `std::variant` |
| `codec` | `encode(Message) → bytes`, `decode(bytes) → std::expected<Message, DecodeError>`; `DecodeError` содержит код, смещение в байтах и индекс команды |
| `validate` | статическая проверка уровня 1 (§9) |
| `graphdef` | структура GraphDef, кодек, валидатор (§13), каноническая форма |
| `catalog` | записи каталога v0, поиск по имени, `catalog_hash()`, каноническая печать |
| `text` | ассемблер и дизассемблер сообщений и графов. Контекст: база времени, имена параметров по def, загрузчик файлов |
| `transport` | путь сокета и проверка прав каталога (§2), `listen`, `connect` (оба выставляют `SO_SNDBUF`), отправка и приём одного сообщения, RAII-дескриптор. Без потоков и без цикла событий — его делают сервер и клиент |

### Готово, когда

- Roundtrip `структура → бинарь → структура` проходит для каждого вида сообщения, команды, вызова,
  результата и события, в том числе на граничных значениях.
- Декодер отклоняет обрезку на каждом байте, несовпадение `length`, лишние байты, неизвестные `kind`
  и opcode, `bool` вне {0, 1}, NaN и Inf, перечисления вне диапазона — и никогда не читает за
  пределами буфера.
- Каждое правило статической проверки и валидации GraphDef покрыто отрицательным тестом.
- Значение `catalog_hash()` зафиксировано в тесте: изменение каталога без обновления теста и версии
  протокола не пройдёт незамеченным.
- Текст: `бинарь → текст → бинарь` даёт те же байты для канонических сообщений и графов; ошибки
  разбора содержат строку и столбец; golden-файлы лежат в `shared/tests/data/`.
- Транспорт проверен на `socketpair(AF_UNIX, SOCK_SEQPACKET)`: отправка и приём, слишком большое
  сообщение, путь сокета с `XDG_RUNTIME_DIR` и без него.
- Есть fuzz-цели для `decode` и разбора текста: meson-опция `fuzz`, только clang + libFuzzer.
- Библиотека стала `static_library('bitvm-proto', …)`, `meson test --suite shared` зелёный, в том
  числе в сборке с `-Db_sanitize=address,undefined`.

## 19. Не входит в v0

- `node.map` — привязка параметра узла к контрольной шине.
- Экспоненциальный ramp (`curve = 1`).
- `buf.write` — запись данных клиента в буфер (волновые таблицы).
- События уровня сигнала (метры) для будущего TUI.
- Захват звука, MIDI.
- TCP-транспорт и удалённые клиенты.
- Правила совместимости версий после 1.0.
