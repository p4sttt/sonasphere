# Завершение M1 и реализация M2

Дата: 2026-11-04. Основание: `architecture.md` §9 и `protocol.md` v0.1.
Пользователь поручил автономно завершить ревью протокола и следующий этап, разрешив менять
архитектурные решения. Исходные незакоммиченные изменения M1 сохраняются; коммиты не создаются.

## Границы и решения

- Протокол остаётся общей моделью данных и двумя кодеками. Интерфейс с виртуальными методами
  для каждого кодека не нужен: замена представления уже происходит через `Message` и `GraphDef`.
- `CompiledGraph` проверяет граф и разрешает операции; `GraphInstance` хранит состояние одного
  синта; `Buses` отвечает только за память сигналов. Подготовка и аллокации происходят до RT.
- `Engine` владеет деревом и расписанием. На аудиостороне фиксированные таблицы, очереди SPSC,
  heap с заранее выделенной ёмкостью и POD-уведомления. Удаление объектов возвращается control.
- `TimeMap` переводит абсолютные наносекунды в первый фрейм не раньше события. Offline использует
  виртуальный ноль. `AudioBackend` отделяет pull-рендер от WAV и памяти.
- Партитура исполняет только CALL/BUNDLE от клиента 1, по порядку файла; вызовы синхронны.
  Запросы дерева/status/reset в M2 разрешены между callback; конкурентный сервер и ALSA — M3.
- Синтаксис sona и каталог v0 не меняются. Семплер и расширенный DSP-каталог остаются M4.

## Порядок работ и проверки

- [x] M1: независимое ревью shared; регрессионные тесты до исправлений. Проверить типизированные
  API на некорректные enum, границы текста и неблокирующее обнаружение существующего сервера.
- [x] DSP: `graph.hpp/.cpp`, `buses.hpp/.cpp`, `tests/dsp.cpp`. Проверить арифметику, sin_osc,
  огибающие и done, rate-преобразования, IR-снимок, ramp, чтение и запись шин, паузу.
- [x] RT-фундамент: `spsc.hpp`, `time_map.hpp/.cpp`; тесты переполнения/обхода кольца,
  конкурентного обмена, дробных фреймов и больших времён.
- [x] Engine: `engine.hpp/.cpp`, `node_tree.hpp/.cpp`; тесты дерева, порядка равных времён, старта внутри блока,
  всех команд, уровня 1, runtime-отката, мягких пропусков, опоздания, пределов и освобождения.
- [x] Offline: `backend.hpp/.cpp`, `score.hpp/.cpp`, `bitvm-render`; тест текстовой и бинарной
  партитур, загрузки графа, детерминированного WAV и точных онсетов при разных размерах callback.
- [x] Интеграция: Meson, русская документация и воспроизводимый пример партитуры. Полный запуск
  `meson test -C build --print-errorlogs`, ASan/UBSan и fuzz shared. Независимое финальное ревью.

## Критерий чекпоинта

Из CLI текстовая или бинарная партитура создаёт WAV. Проверка сэмплов подтверждает точное положение
начала/конца нот, предсказуемый порядок и корректные ошибки. Callback не выделяет/удаляет память,
не использует блокировки или I/O. Все операции каталога v0 имеют реализацию и тесты.
