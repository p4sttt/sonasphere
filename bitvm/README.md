# bitvm — звук, время, вычисления

Аудиодвижок и демон `bitvmd`. Принимает поток команд из `shared/`, исполняет DSP-графы с точностью
до сэмпла и отдаёт звук в бэкенд (ALSA, offline).

Про язык sona не знает ничего: ни ключевых слов, ни темпа, ни имён сэмплов, ни файлов `.sona`.

- `include/bitvm/` — API движка для bitvmd, утилит и тестов
- `src/engine.cpp` — подготовка команд, расписание и граница control/audio
- `src/node_tree.*` — таблица ID, порядок исполнения и операции над поддеревьями
- `src/graph.cpp`, `src/buses.cpp` — скомпилированные DSP-графы, состояние синтов и шины
- `src/time_map.cpp` — перевод абсолютного времени в фреймы
- `src/score.cpp`, `src/backend.cpp` — партитуры и offline-выход в память или WAV
- `bitvmd/` — демон
- `tools/render.cpp` — `bitvm-render`; будущий IPC-клиент `bitvmctl` зависит только от протокола
- `tests/` — gtest; новый тест = имя в списке в `tests/meson.build`

Подробности — `docs/architecture.md`, §5.

## Offline-рендер (M2)

```bash
meson compile -C build
build/bitvm/bitvm-render --duration 2 examples/offline/ping.bvs build/ping.wav
meson test -C build --suite bitvm --print-errorlogs
```

Вход — текстовая партитура `.bvs` или бинарная `.bvsb` из `docs/protocol.md` §16. Пути к `.bvg`
и аудиофайлам разрешаются относительно партитуры. Поддержаны именованные параметры графов.
Без `--duration` рендер заканчивается через секунду после последнего бандла; явная длительность
должна включать все события. Предел — 24 часа, WAV дополнительно ограничен размером RIFF (~4 ГиБ).
Флаги `--sample-rate` и `--channels` меняют формат выхода; по умолчанию 48 кГц, стерео, float32.
Файл записывается потоково, бэкенд памяти хранит весь результат в памяти вызывающей программы.

Все юниты каталога v0 реализованы. Создания и удаления точны до сэмпла, параметры меняются с ramp,
пауза останавливает состояние синта. Сетевой демон, ALSA и `bitvmctl` — следующий этап M3.

Для встраивания: создайте `Engine`, загрузите граф через `call(DefLoad)`, передайте бандлы через
`submit`, запрашивайте interleaved-сэмплы через `process`, а на control-стороне вызывайте `collect`
и читайте уведомления. Callback не делает аллокаций, удаления объектов, блокировок или I/O.
Запросы ресурсов и состояния в M2 выполняются между callback; подробный контракт — в `engine.hpp`.
